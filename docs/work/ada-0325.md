## Scope

Profile steady flight in a light and a dark galaxy, the local map while panning, the station
shop and job board, and the start screen at 4x CPU throttle, at 1280x720 and at 720x360 with
phone insets. Fix the measured hotspots that have one clear fix and change no visuals, rules or
behaviour. Report the rest for a user decision. The story page, the restart card, resize
memory, SVG re-rasterising, the loader and Phaser beams and missile blasts stay with their own
items.

## Criteria

- Before and after profiles of the same scenarios on builds that differ only by the fixes.
- Each fix in its own commit, with a focused unit test where it is testable.
- The full gate and the browser smoke pass on the exact revision.

## Decisions

- Scan receipts read their HUD, touch control, HUD row and conversation footprints through
  functions, so the receipt queue measures the DOM only when it places or shows a receipt. Every
  frame measured all four before, receipt or none.
- Penny markers measure the HUD footprints only when there are markers to place.
- Dust specks draw only where their circle meets the camera's world view, grown past a hit
  shake's reach. The speck grid spans the whole projected diamond around the screen, so about 25
  of its 361 specks fall in view.

revision with the three fixes. Game loop is Phaser's animation frame callback, median / p90 /

median / p90 animation frame interval, in ms.

The game loop drops by a third to a half on the map, station and start screen. Flight in
Cartwheel is dominated by enemy obstacle avoidance near the hub's scenery (about 60% of the game
loop), so its game loop stays within run-to-run noise there; its renderConversation and Graphics
work fall as elsewhere. Frame intervals barely move: headless Chromium presents the WebGL canvas
in software, about 1.3 to 2.3 s of each window on the main thread, which a GPU device does
elsewhere. The station shop and job board maxima after are single major collections.
