## Scope

Request an ordinary update check when Ada returns to Start without reloading
the document. Use the published Game Kit update lifecycle and keep explicit
Update now, the current cooldown, offline play and saved progress.

## Criteria

- Check on a genuine return to Start. Coalesce repeated returns and normal
  reconnect or foreground events through the existing cooldown. Use the
  same visibility, online and staging guards as other checks.
- Keep the current version active while staging. Show the normal update
  prompt for a verified newer build. An explicit acceptance navigates once,
  and deferral keeps the current session playable.
- Test a browser document opened on the current public build before a normal
  deployment. After deployment, return to Start in the same document and
  record the request, staged version and prompt. Verify acceptance and save
  continuity. Record any physical-device limits separately.

## Decisions

## Outcome

Ada checks when returning to Start from play. The public browser test
opened on `4d493832` and stayed visible while `fdd76220` deployed.
Continue, Pause and Back to title made one discovery request in that
same document. The old build stayed active while the verified update
was staged. Update now caused one navigation and preserved the saved
campaign and exact save bytes. Chromium verified this browser path;
physical installed-app behavior was outside this test.
