## Scope

Overlap installed-game version discovery with startup and keep the existing
progress indicator meaningful while an update prepares, downloads and applies.
Consume the shared change through the published Game Kit package.

## Criteria

- Start one real version check earlier without delaying Start on slow or
  unreachable servers. Keep normal retry and verified staging.
- Show preparation once a successor is confirmed, real byte progress during
  download, and activation through the reload into the new build.
- Preserve explicit acceptance, save and version checks, one navigation, and
  offline play. Measure the new timing in an older installed browser profile.

## Decisions

- D1 (user, 2026-11-27; answers q-ada-update-discovery-during-play): Keep current check triggers

## Outcome

Build `7bbdd342` shipped Game Kit 0.94.1. It overlaps the installed game's
startup check with title startup and shows preparation, byte transfer and
activation on the existing progress rail. Existing discovery triggers and
explicit update confirmation remain.

In a controlled installed Chromium run, Continue appeared after 2.602 seconds
while the build response was still held for another 1.399 seconds. One build
request was issued. The installed browser also updated from production
`15e44060` to production `7bbdd342`. The Update now action caused one
navigation, 758 ms after confirmation. The exact save and five configured
settings survived, and Continue worked offline on the new version.
