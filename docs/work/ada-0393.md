## Scope

Arrange shipped source into named layers with imports pointing down only, one
public entry per area, effects injected at the edges, and no test-only
production paths, following the shared procedural systems policy
(game-coordinator gc-0028) and the shared source-structure policy
(game-coordinator gc-0029). Each step preserves behaviour except the procedural
items carried over from ada-0392.

## Criteria

- Layers map onto the shared source-structure bands (game-coordinator gc-0029),
  lowest first: Foundation (lib, authored data), Model (model), Saving (save
  and progress code split out of model), Presentation (art, layout and input
  state), Platform (loading, pwa runtime, crash logic), Engine and views (ui,
  then scene), Entries (entry), Support (`src/build`, tools, test harness).
  Scene sits above ui; non-Phaser files in `src/game` move into art; DOM code in
  crash and loading moves into Engine and views.
- Data sits below model: `Vec`, `CheatId`, `MapSymbol` and `ExchangeRates` move
  below model. `model/ai` and `model/flight` are sub-folders, not layers.
- Authored data files are imported directly; every other area, layout included,
  has one public entry file.
- Build-time code lives in `src/build/`; source scanners used by tools move to
  `tools/`.
- No runtime import cycles. Type-only imports point down too, but may form
  cycles within one band.
- Decisions read no `crypto`, `performance`, `Date` or `localStorage`; entropy,
  frame time and storage are passed in.
- `flight.ts` splits into `src/model/flight/` and `GameModel` into pure parts
  behind the class.
- Duplicated helpers are shared from `src/lib` or Game Kit.
- From ada-0392: named random streams with saved draw counts for resumable
  runs, one refusal-reason predicate per admit or refuse decision, and no routine
  pacing simulation in the test suite.
- During the migration, one temporary import check places every module in a
  band and fails on a runtime cycle, a wrong-direction import (type-only
  included) or an unplaced module, apart from a known-violations table that only
  shrinks. When the table is empty the check is removed and ESLint guards the
  layers.

## Decisions

- Scene above ui, with non-Phaser game files in an art layer below ui.
- Data below model.
- The import check lands early with a shrinking known-violations table, then
  ESLint guards the layers once the table is empty (user, matching all games).
- Staged order: build-code move, dead code and effect injection now; type
  cycles after ada-0380; the `src/game` split after ada-0385; ui moves with
  ada-0390; the `flight.ts` and `GameModel` splits after ada-0380.
- One entry file for every area except authored data files, matching the
  shared layer policy drafted with Chibi and Archie.
- Build code in `src/build/`.
- Supersedes ada-0392.

## Outcome

ESLint checks the shared layer order, including type imports, and reports
runtime cycles in the full import graph. It also checks that production
callers use the public entries of completed areas.
Vite loads the project plugins through the single build entry.
Co-located test fixtures with the `.fixture.ts` suffix belong to Support
and are unavailable to runtime code.

The boot font and bitmap observers run in the UI layer. Loading coordinates
resource readiness through the existing registry and a structural UI
resource contract. Bootstrap and the reveal fallback use the same observers.
The loading and offline areas guard their public entries. The worker
and build use the standalone cache policy, and startup uses the
installation relay without loading the browser launch code.

Model and authored data lint rejects direct reads of browser storage, time
and entropy. The model takes these inputs through the surrounding application.

The Flight entry delegates ship contact, debris motion, pickups, player
weapon release, enemy beam lifecycles and miner patrol acquisition to
private model modules. GameModel
keeps its public interface while campaign initialization, early routes,
docked shop queries, Map Travel target selection, job scenery, Quest Details
and Storybook projections live in separate modules. Saving reads campaign
initialization and route helpers directly. Existing save, restart, combat
and navigation tests cover the extracted paths.

Hostile-station readers and save validation share a lower entry. Live
placement, materialization and rewards have explicit entry modules, so
Saving and procedural site lookup can load the readers without pulling
in station materialization. Saving reads Needle, Andromeda and Phantom
state and the authored route tables without loading chapter or flight
runtimes. A dependency test checks this through the public Saving entry.

Achievements, Cheats, Conversation, Exchange, Flight feedback, Galaxy selector,
Menu, Pause, Quest Log, Resource, Restart, Settings, Ship, Start, Station and
Weapon Detail each have a dedicated UI area with one public entry. Their view
tests stay with their implementations.

The game entry uses the guarded Scene interface for Phaser construction and
view refresh.

Local Map layout calculations have a separate entry from the DOM screen.
The layout dump retains its existing module names and output.

The shared layout layer exposes geometry and tokens through a Node-compatible
entry. The UI layer owns the live frame measurements and view-scale bridge.
Startup and recovery retain their narrow imports. The layout dump and early
bundle edges were identical in the paired build.

World coordinates use a shared model entry. Enemy AI exposes its engine
and a separate world-navigation entry, so Saving can use navigation
without loading the enemy hull assets. Friendly station readers, commerce,
the primary grid, and formations have separate entries to keep
retained-landmark lookup and station placement acyclic. Needle course
geometry exposes a named public interface, with separate ports for
contact, persistence, and chapter runtime.

Andromeda keeps its authored places, lane geometry, persisted state, and
relay reads separate from chapter and encounter runtime. Phantom has
separate chapter, authored, state, placement, pending, reservation and
ally entries. Its lower entries keep the same runtime dependency graph
as before the move. Cartwheel claim fields, mining patrols, and authored
sites use separate entries to keep the sites readable independently.
Procedural spawn planning,
encounter spacing and target selection use separate entries so reading
the hostile schedule does not load the planner or POI generation.

Startup and gameplay share one action ownership entry for registration,
dispatch, and press scope. Gameplay text button production stays
outside that startup entry. The construction checker verifies the
original binding declaration through explicit named re-exports.

Route guard displacement draws one heading from the named Game Kit stream
for that actor. An obstructed guard can take a different heading. Matched
replays retained formation admission, the anchored guards and wrapped
clearance through Continue. The draw ends within the operation.

The encounter and hostile-station population checks share one predicate
with typed refusal reasons. Registration and the existing local,
archetype and capital limits keep their evaluation order.

The remaining layer moves and public entry consolidation are open.
