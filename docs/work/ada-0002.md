## Scope

Reduce the test suite's runtime while preserving coverage of realistic user scenarios and
plausible critical edge cases. There is no fixed case-count target.

The browser smoke's runtime is in scope.

The smoke must come back under 420 seconds; its 600 second limit is a hang guard.

## Criteria

- Baseline and after case counts and runtime are recorded separately, with comparable suite scope
  and execution settings.
- The achieved runtime and case-count changes are reported, and accepted coverage losses in
  low-risk, low-churn areas are documented.
- No failing test is deleted, no timeout is weakened, and no mass mutation campaign or new test
  matrix is added.
- No application change.

## Decisions

- Shared tables and helpers are preferred over repeated test bodies; parameterization alone is
  not pruning.

## Outcome

Comparable browser smoke fell from 425.306 s to 413.509 s with all 70 checks retained.
The watchdog is 600 s. Focused station tests fell from 3.86–4.33 s to 0.97–1.00 s
with all 16 cases and all 1,383,840 station-distance comparisons retained.
Negative probes verify that the resize checks reject stale uploads and excess
textures, and that grid spacing rejects a close pair and nonfinite distances.
No application behavior or test coverage changed.
