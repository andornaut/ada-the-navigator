## Scope

Investigate. With 4x CPU throttle on the holodisk story page, the game's `requestAnimationFrame` callbacks take 14 to 64 ms per frame, the main thread is about 98% busy with a 33 ms median frame interval, and the holodisk swaps fire late. Find what runs per frame on story pages (Phaser scene update and render, the flight model step, the HUD, the backdrop) and whether the flight scene keeps simulating or rendering behind the storybook. Report the cause with trace evidence and one proposed fix; code changes need a separate approval.

## Criteria

- Per-frame main-thread work on the holodisk story page is attributed from throttled traces.
- One fix is proposed for the user's decision.

## Decisions

## Outcome

The flight scene kept rendering every frame behind the opaque storybook. The flight model was
paused by the holodisk moment's dialogue marker, but `GameScene.update` still ran `refreshScene`,
`draw` and `renderConversation`, Phaser rendered the full flight frame and the browser presented
the WebGL canvas. At 4x throttle on the holodisk page that was about 13 ms of script (6.6 ms
Phaser render, 5.9 ms scene update) plus about 21 ms of canvas present per frame, so frames
landed every 33 ms. `refreshScene` also closed the restart card every frame, rebuilding its
layout with style reads. The user approved fixing both, as [ada-0315](ada-0315.md) and [ada-0316](ada-0316.md).
