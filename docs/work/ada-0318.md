## Scope

On a portrait touch screen the page frame turns a quarter turn, and `getBoundingClientRect`
measures on the page, so its width and height swap and its edges move to other sides. The scan
receipt measured its panel that way and drew as a vertical bar. Every layout measurement reads
boxes in the frame's own axes through one shared helper; pointer hit tests keep page coordinates.

## Criteria

- Every `getBoundingClientRect` use in `src` is audited: layout reads sizes, edges and the device
  pixel grid through `src/ui/layout/frameBox.ts`, and a source test lists the uses that read page
  boxes, each with its reason.
- The scan receipt, Settings, story page controls, station shop and jobs lists, the shield pill's
  pixel snap, the local map's pointer mapping and the layout-tree measurements are correct in a
  turned frame.
- A unit test for each helper; a browser smoke proof of the scan receipt in a fresh turned
  396x744 CSS page.

## Decisions

- Pointer hit tests (`elementFromPoint`) and the canvas pointer mapping keep page coordinates; the
  local map's pointer mapping turns them into the frame's axes.

## Outcome

Shipped in the commit that adds this file. In the turned 396x744 CSS frame the scan receipt lays
out wider than tall, its page box the layout box turned.
