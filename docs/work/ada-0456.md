## Scope

Use one registration interface to declare the keys and mouse buttons for each
behavior and the context where it is available. Keep action callbacks and
player-facing labels in the game. Assess whether the reusable part belongs in
Game Kit so other games can adopt it.

## Criteria

- Make bindings discoverable from their declarations, including distinct
  mappings for flight and menu contexts.
- Preserve current input behavior, including held controls, discrete presses,
  aliases, modifiers, repeat, cancellation and dispatch to the active surface.
- Verify single dispatch and no input leakage across active flight, menus,
  edits and lifecycle changes. Keep the approved touch behavior.
- Check the shared interface against Ada, Archie and Chibi needs. Reuse an
  existing Game Kit interface where it fits, or coordinate a shared proposal
  with its owner.

## Outcome

Build `7d0bf2d8` uses a typed, context-scoped binding index for flight
and the title shortcut. The index separates keyboard and mouse input
and rejects collisions inside a context. Game Kit's foreground router
keeps menu focus, activation, Escape and right-click dispatch. Focused
checks covered modifiers, held fire, single Use dispatch and the
existing guarded title shortcut.

Game Kit reviewed the shared seam against Ada, Archie and Chibi. A
future reusable index could carry modifier matching and trigger
metadata. Context admission, held state, callbacks and labels stay
with callers. The game uses the existing public API.
